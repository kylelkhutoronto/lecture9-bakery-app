Home Bakery order desk

Track orders from Instagram, protect each day’s baking capacity, and keep a clear record of the baker’s decisions.

Start the app

  1. Open this folder in File Explorer. Click the address bar, type powershell, and press Enter.
  2. Type python app.py and press Enter.
  3. Open http://127.0.0.1:8000 in your browser.

Keep that PowerShell window open while using the app. Press Ctrl+C there to stop. Your decisions are saved automatically. To return later, repeat these steps.

If Windows does not recognize python, try py app.py. If port 8000 is already in use, stop the other app using that port before starting this one. No packages or installs are needed when Python is available.

Use the order desk

  1. Start on Monday 23 November 2026. The app uses a saved classroom date, independent of your computer clock. All 13 existing orders are already accepted. The 25 supplied messages arrive across Monday–Sunday as you move through the week.
  2. Read the inbox. Each message shows the original text, source file, request number, and a fixed-rule eligibility explanation. Click Accept order, Approve change, or Apply cancellation. Reject request is always available for an arrived pending message; an optional reason is saved.
  3. Watch the baking calendar. It shows accepted work, remaining time, and helper bookings for the displayed week. Pending requests reserve no space, so accepting one can change whether another fits.
  4. Book help when needed. Use + Helper on a calendar day, or the date form below the calendar. Booking adds four hours and costs $100, with two days’ notice. The app never hires automatically.
  5. Finish the day. Decide all arrived pending requests first. Finish day moves the saved date forward one calendar day and reveals the next day’s messages. This cannot be undone in the interface. Review capacity and helper needs before advancing, especially for Saturday.
  6. Manage pickups. Filter the order book by customer, order number, date, or status. On the pickup day, mark an accepted order ready, then collected. All pickups are at 5 PM. The status buttons are manual confirmations; there is no live clock cutoff or reminder service.
  7. Record more requests. The form records a new order, change, or cancellation received on the displayed day. For changes and cancellations, use the original customer name and pickup date. The request goes to the inbox for review. A date change requires a cancellation and a new order; both must meet notice rules.
  8. Review and export. Decision history preserves original messages and reasons. The activity log records decisions, helper bookings, timeline changes, and fulfillment. Export all orders (CSV) provides the full order book, regardless of current filters.

Goals and rules

The goal is to help a home baker manage cupcake and cake orders, changes, cancellations, capacity, helper costs, and pickup status. The baker retains every accept/reject decision. The system does not send Instagram replies or connect to an Instagram account.

  • One product per order. Quantities are positive whole numbers of dozens or cakes.
  • All baking happens on pickup day. Daily capacity is eight hours; one helper raises it to twelve hours. Helper cost is $100 for that day.
  • Orders, changes, cancellations, and helper bookings require two calendar days’ notice. Monday for Wednesday qualifies; Monday for Tuesday does not. Notice uses dates, not a rolling 48-hour clock.
  • Request notice is measured from the message’s received date. Helper notice is measured from the displayed booking date. Requests for days that have passed cannot be approved.
  • Changes replace an accepted order’s product/quantity; capacity is recalculated without double-counting the original. Cancellations free the original hours and remove its sales from totals.
  • Only exactly one matching accepted order can be changed or cancelled. Resolve a customer’s earlier new-order request first. Ready, collected, and cancelled orders cannot be changed. Rejected changes leave the original order intact.
  • Ready and collected orders still consume their pickup day’s capacity. Existing orders are treated as commitments made before Monday; their original received dates are not supplied.
  • Cakes usually arrive a week ahead, cupcakes mainly in the last three days, and Saturday is usually busiest. These are planning hints from the source pages, not additional deadlines.

Implementation details

  • app.py contains the Python HTTP server, HTML/CSS interface, source import parser, SQLite schema, and all fixed business rules. It uses only Python’s standard library. The page works with ordinary HTML forms; JavaScript is not required.
  • bakery.db is the single persistent data file beside the app. Tables: orders, requests, helpers, settings, and audit. All 25 original message bodies and source identifiers are retained. There is no AI, Node.js, npm, external font, or external API.
  • The server binds only to 127.0.0.1:8000. It serves only the app, this help page, and the CSV export. It does not expose arbitrary folder files. Browser form submissions are checked for cross-origin requests; user text is HTML-escaped, SQL uses parameters, and exported customer names are protected against spreadsheet formulas.
  • Business mutations use transactions and recheck rules immediately before saving, preventing duplicate decisions and overbooking across tabs. Failed actions roll back and display an explanation. Successful form submissions redirect to prevent refresh from repeating them.
  • Hours are stored/calculated in integer minutes and prices in whole dollars. Totals show committed sales, helper costs, and their difference. This difference is not profit: ingredient costs, taxes, payment collection, and other expenses are outside the supplied requirements.
  • Interpretation: at most one helper per day. Helper bookings are final in the interface because no helper cancellation/refund policy was supplied. There is no automatic optimization or ranking of customers.
  • The app and its files are independent of the Lecture 9 Workflow Builder. No Workflow Builder files are required or changed.

Saved data and checks

To back up your work, stop the app and copy bakery.db somewhere safe. To restore, stop the app and replace it with that backup. Keep the source CSV and seven HTML pages beside app.py for first-time setup. Editing those sources after initial setup does not reimport them; record additional requests through the app.

test_bakery.py runs automated business-rule checks on temporary copies made using SQLite’s backup API. It never writes to the real database. After the app has created bakery.db, run python -m unittest -v test_bakery.py from this folder. The suite expects the initial Monday dataset; run it before entering your own decisions. It checks notice, capacity, helpers, changes, cancellations, fulfillment, import idempotence, rollback, and the complete supplied week.

Future use beyond this exercise: the timeline can continue forward and manual requests can be added, but the seven supplied files provide no messages after Sunday. There is no reset button, login, payment processing, automatic scheduling, or connection to live Instagram.
